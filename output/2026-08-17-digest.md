### Tips & Tutorials

- **[Auto Mode Deep Dive: What the New Default Actually Does](https://code.claude.com/docs/en/changelog)**
  Auto mode uses a classifier to evaluate every tool call before execution — it's not blanket-allow. The community recommends auditing your `CLAUDE.md` deny lists and sandbox configs now that auto mode is default, since the classifier's decisions are logged but hard to audit after the fact. Use `CLAUDE_CODE_TOOL_MEMORY_LIMIT` on Linux to add a budget guard on Bash tool invocations.

- **[Configuring WebFetch Cache TTL (New Env Var — Aug 14)](https://code.claude.com/docs/en/changelog)**
  New `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` environment variable lets you control how long WebFetch caches URLs per session (default: 15 minutes). Set it lower for pages with rapid content turnover (e.g. live dashboards), higher to reduce egress in long sessions fetching stable documentation.

- **[Server-Supplied Hooks for Self-Hosted Runner Sessions (v2.1.229)](https://code.claude.com/docs/en/changelog)**
  Self-hosted runner sessions now support server-supplied Claude Code hooks, matching the behavior of managed cloud environments. Pair with `claude remote-control --continue` (now documented) to resume the most recent Remote Control session without needing the session ID.

- **[SSE Keepalive Pings Fix Idle Timeouts on Vertex/Bedrock (v2.1.229)](https://code.claude.com/docs/en/changelog)**
  Gateway streaming now sends SSE keepalive pings during long thinking pauses, preventing idle-timeout disconnects on Vertex AI and Amazon Bedrock upstreams. If your Bedrock or Vertex integrations were dropping mid-stream on complex reasoning tasks, update to v2.1.229+.
